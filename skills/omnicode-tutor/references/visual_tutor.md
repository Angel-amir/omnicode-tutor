# Visual Code Tutor (Python Tutor Clone)

## When to use this skill
Triggered when the user asks:
- "Trace this code"
- "Step by step"
- "What is happening internally with these variables?"

## Execution Rules
This skill uses **Generative UI** (embedded interactive HTML/JS) to emulate Python Tutor.

### 1. Check for Pre-baked Templates (CRITICAL STEP)
Before generating a custom HTML widget from scratch, use the `list_dir` tool to check the `skills/omnicode-tutor/templates/visual_tutor/` directory.
- If there is a generic UI shell that matches the core concept of the code (e.g., `iteration_slider.html` for loops, or `call_stack.html` for recursion), you MUST use the `view_file` tool to read it.
- Copy that HTML shell exactly. To adapt it to the user's code, you must ONLY inject their specific code and the step-by-step execution data (as a JSON array) into the designated `<script>` block contract of the template. DO NOT alter the HTML/CSS structure of the shell.
- If NO suitable template exists for the requested concept, fall back to generating a custom widget from scratch.

### 2. Custom Widget Construction (Fallback)
If no template exists, the widget must have this strict structure:
1. **Code Panel:** The exact code block provided by the user (or generated by the data simulator).
2. **Animated Arrow:** A visual marker (highlight or arrow) that advances line by line when pressing "Next".
3. **Memory and Variables:** A panel showing the current value of each variable (e.g., `i = 0`, `array = [1, 2]`). Value updates must have CSS transitions (e.g., color flashes) to highlight the change.
4. **Bottom Explanation:** Text explaining the exact logic of THAT particular line of code.

Key difference: Unlike the `animator` (which abstracts macro-level concepts like VisuAlgo), THIS skill is strictly for micro-logic debugging and variable tracking.
